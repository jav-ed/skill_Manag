# linker_Review_Rounds

Two adversarial reviews of the Rust rewrite, done read-only by a second Claude session on 2026-10-07 and 2026-10-08: round 1 read `Crates/Core`, round 2 read the code written after it (profiles, project creation, config saving, apply changes, the command line, the terminal interface). Each finding has a severity, a location, a scenario, a proposed fix and a status. Round 1 findings are fixed and carry the test that now covers them; round 2 findings are open. The tree state each file was checked against is stated inside it; a half-built backup module in the tree has not been reviewed.

## Docs

- [Round 1, Core](round_1_Core.md): 2 High, 6 Medium, 8 Low and 3 Info findings about scan, vault, plan, apply, delete and config, each marked fixed or open, with the exact test name in `Crates/Core` that covers every fixed one. Open it to learn why a guard exists (`exclude_paths` with a `..` root, untracked `SKILL.md`, edits made after planning, symlinked `.agents`, non-UTF-8 names), to find the test behind a rule, or to see what round 1 left open (unmerged index entries, no fsync by decision).
- [Round 2, Full](round_2_Full.md): 6 Medium and 12 Low open findings plus the missing-tests table, covering the terminal interface (planning after Enter, job results on the wrong screen, setup order, Ctrl-C mid-job), apply (cleanup race, snapshot gaps), `save_config` (symlinks, comments, CRLF, valid lists it refuses), profiles (exponential diamonds, exclude order) and `init`. Open it before fixing any of those, or to check whether a behavior you see is already known.
- [Review method](review_Method.md): how the reviews were done without touching the working tree (throwaway copy, tree hash, print-only reproducers), the techniques that found real bugs (draw fuzz over terminal sizes, race loops, text-edit matrices, event-order tests, read-only runs on real data), what a round 3 should cover (the backup module first) and ideas not yet tried. Open it to repeat a review or to plan one.
- [Reproducers](Repro/readme_Repro.md): the runnable Rust tests and the shell script behind round 2, where each file belongs in the repository, the exact commands, and for each series the output that proves the bug while it is open and the output that must appear once it is fixed. Open it to confirm a finding, to turn a reproducer into an asserting test, or to check a fix.
